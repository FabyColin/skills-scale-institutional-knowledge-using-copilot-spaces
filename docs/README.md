# OctoAcme Project Management Docs

This folder contains OctoAcme's core project management process documents. It is intended to be the central entry point for team members who need to understand how work is planned, executed, communicated, released, and improved across the project lifecycle.

## Project management process summary

OctoAcme uses a lightweight, iterative delivery model that keeps work customer-focused and measurable. Projects begin with initiation, where the problem, stakeholders, goals, and success metrics are defined in a Project One-pager and aligned with the business case. Once approved, the team moves into planning, where scope is translated into a prioritized backlog, milestones, dependencies, estimates, and a clear Definition of Done.

During execution, work is tracked on a project board through stages such as Backlog, Ready, In Progress, In Review, QA, and Done. Teams follow a regular cadence that includes daily standups, weekly delivery syncs, PM + PdM alignment, demos, and periodic stakeholder updates. Communication is supported by a risk register, escalation paths, and status reporting so progress, blockers, and decisions stay visible.

Quality is built into the process rather than added at the end. PRs are expected to be small, reference the relevant issue and acceptance criteria, and pass CI checks such as tests, linting, and security scanning before review. QA validates acceptance criteria and release readiness, while releases follow deployment checklists, smoke tests, rollback plans, and post-release verification. Retrospectives and continuous improvement loops convert lessons learned into action items tracked in backlog work.

## How to use these docs

Start with the project management overview to understand the principles and lifecycle, then move into initiation and planning before execution and release work. Use the role and risk documents as needed for ownership, communication, and escalation guidance. This structure helps new team members onboard quickly and gives the broader team a shared source of truth for project management practices.
